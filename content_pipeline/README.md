# ابزار استخراج و تحلیل خوراک محتوایی

ابزار CLI پایتونی برای استخراج عناوین محصولات از سایت‌های رقیب، ادغام هوشمند
نام‌های تکراری، و تفکیک محصولات دارای ساجست از بدون ساجست.

**هزینه‌ی API: صفر.** هیچ سرویس پولی استفاده نمی‌شود.

---

## خروجی

سه شیت در یک فایل اکسل (یا یک گوگل‌شیت):

**شیت A — «آماده تولید محتوا»** (`has_suggest`)

| ستون | توضیح |
|---|---|
| `canonical_title` | عنوان یکپارچه |
| `lsi_keywords` | کلمات پیشنهادی گوگل، جدا شده با `\|` |
| `lsi_count` | تعداد ساجست‌ها (برای اولویت‌بندی) |
| `source_domains` | دامنه‌هایی که این محصول در آن‌ها بود |
| `source_urls` | لینک‌های اصلی |
| `merge_count` | چند عنوان خام در این رکورد ادغام شده |
| `confidence` | امتیاز اطمینان ادغام |

**شیت B — «آرشیو آینده»** (`no_suggest`) — همان ستون‌ها بدون `lsi_keywords`.

**شیت C — «نیاز به بازبینی دستی»** — دو نوع ردیف با ستون `type`:
«ادغام مبهم» (ابزار مطمئن نبود ادغام کند یا نه) و «ارتباط مرزی با موضوع»
(امتیاز موضوعی بین دو آستانه).

## نصب

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r content_pipeline/requirements.txt
playwright install chromium        # فقط اگر سایت JS-heavy دارید

cp content_pipeline/config.example.yaml config.yaml
```

**حداقل وابستگی‌ها `typer` و `PyYAML` است.** بقیه اختیاری‌اند و پایپ‌لاین بدون
آن‌ها هم اجرا می‌شود، ولی با کیفیت یا ریسک بیشتر:

| بسته | نبود آن یعنی |
|---|---|
| `curl_cffi` | برگشت به urllib کتابخانه‌ی استاندارد — اثرانگشت TLS شناسایی می‌شود (CLI هشدار می‌دهد) |
| `rapidfuzz` | شباهت با `difflib` (کندتر، نتیجه‌ی مشابه) |
| `sentence-transformers` | انکودر جایگزین hashing tf-idf — تشخیص موضوعی ضعیف‌تر |
| `selectolax` | `title_selector` سفارشی کار نمی‌کند (h1/og:title/title کار می‌کنند) |
| `openpyxl` | خروجی به‌جای xlsx، سه فایل CSV |
| `playwright` | سایت‌های JS-heavy عنوان نمی‌دهند |

## اجرا

```bash
# ساخت دیتابیس
python -m content_pipeline.run init-db -c config.yaml

# اجرای کامل (چهار فاز)
python -m content_pipeline.run start -c config.yaml

# ادامه از فاز ۳ روی آخرین اجرا (فازهای ۱ و ۲ تکرار نمی‌شوند)
python -m content_pipeline.run start -c config.yaml --resume-from 3

# فقط چند فاز مشخص
python -m content_pipeline.run start -c config.yaml --phases 1,2

# یک فاز روی یک اجرای مشخص
python -m content_pipeline.run phase 3 -c config.yaml --run-id 20260816-101500-ab12cd

# وضعیت، فهرست اجراها و ساخت دوباره‌ی خروجی
python -m content_pipeline.run status -c config.yaml
python -m content_pipeline.run runs   -c config.yaml
python -m content_pipeline.run export -c config.yaml --no-sheets

# ابزار کمکی: دیدن خروجی فاز ۰ روی یک متن
python -m content_pipeline.run normalize "دانلود جزوه ریاضی ۱۴۰۴ PDF"
```

> `start` بدون `--run-id` و بدون `--resume-from` همیشه یک اجرای **جدید** می‌سازد.
> با `--resume-from N` آخرین اجرای همان موضوع ادامه پیدا می‌کند.

## معماری

```
content_pipeline/
├── run.py                  نقطه ورود CLI
├── config.example.yaml     موضوع هدف، سایت‌ها، نمونه‌عنوان‌ها، آستانه‌ها
├── core/
│   ├── db.py               اسکیما و لایه‌ی state
│   ├── normalizer.py       فاز ۰ — نرمال‌سازی فارسی
│   ├── cache.py            کش کوئری‌های ساجست
│   ├── suggest.py          کلاینت گوگل ساجست + قواعد ایمنی
│   ├── entities.py         توکن تمایزدهنده (مرحله B فاز ۲)
│   ├── similarity.py       شباهت متنی (rapidfuzz / difflib)
│   ├── embeddings.py       بردارسازی (e5 / hashing tf-idf)
│   ├── extract.py          پارس HTML و sitemap
│   ├── http.py             curl_cffi + robots + rate limit + Playwright
│   └── config.py           بارگذاری config
├── phases/
│   ├── p1_crawl.py
│   ├── p2_resolve.py
│   └── p3_suggest.py
├── output/
│   └── exporter.py         سه شیت (اکسل / گوگل‌شیت)
├── tests/                  ۱۳۸ تست، بدون شبکه
└── data/                   runs.db و خروجی‌ها (در git نیست)
```

اصولی که در کد اعمال شده‌اند:

1. چهار فاز مستقل؛ ارتباط فقط از طریق SQLite
2. هر فاز نتیجه را بلافاصله می‌نویسد — هیچ‌چیز فقط در RAM نمی‌ماند
3. `--resume-from N` کار می‌کند (فاز ۳ فقط محصولات بدون وضعیت را می‌گیرد)
4. Idempotent: `UNIQUE` + `INSERT OR IGNORE` در هر جدول
5. هر کوئری ساجست یک‌بار زده می‌شود و در `api_cache` می‌ماند

## فازها

### فاز ۰ — نرمال‌سازی فارسی (پیش‌نیاز حیاتی)

`core/normalizer.py`. هر عنوان قبل از هر پردازشی از این خط عبور می‌کند:

- `ي`/`ك` عربی → `ی`/`ک` (به‌علاوه `ة`، `أ`، `إ`، `ؤ`، `ئ`، `ۀ`)
- یکسان‌سازی نیم‌فاصله و حذف نیم‌فاصله‌های اضافه (و «ه‌ی/ه‌ای» اضافه)
- یکسان‌سازی ارقام (پیش‌فرض فارسی، ثابت و یک‌طرفه)
- حذف اعراب و کشیده
- حذف کلمات ایستای تجاری: دانلود، خرید، رایگان، pdf، فایل، کامل، جدید، نسخه،
  اورجینال و سال‌ها (۱۴۰۳، ۱۴۰۴، ...)
- نرمال‌سازی فاصله‌های چندگانه و trim

`raw_title` دست‌نخورده می‌ماند؛ خروجی در `normalized_title`.
`tests/test_normalizer.py` روی **۲۰ نمونه‌ی واقعی** اجرا می‌شود — عنوان‌های سایت
خودتان را به `REAL_SAMPLES` اضافه کنید.

### فاز ۱ — کراول و تشخیص موضوعی

`robots.txt` → `sitemap.xml` (+ ایندکس‌ها) → در نبودشان کراول محدود با
`max_depth`. هر صفحه با `curl_cffi` و `impersonate="chrome"`؛ روی ۴۰۳/۴۲۹/۵۰۳ یا
صفحه‌ی پوسته‌ای، fallback به Playwright. حداکثر ۱ درخواست در ثانیه به هر دامنه و
احترام به `robots.txt`.

عنوان به ترتیب از `<h1>` → `og:title` → `<title>` (با حذف نام سایت). نام سایت
فقط وقتی حذف می‌شود که قابل اثبات باشد — از `og:site_name`، نام دامنه، یا
`site_name` در config. اگر شناسایی نشد، عنوان دست‌نخورده می‌ماند تا توکن
تمایزدهنده‌ای مثل «جلد دوم» تصادفاً حذف نشود.

`score >= 0.65` مرتبط، `0.50..0.65` به شیت C، کمتر رد.

### فاز ۲ — Entity Resolution (حساس‌ترین فاز)

| مرحله | کار |
|---|---|
| A | بلاک‌بندی بر اساس نادرترین کلمات عنوان پایه |
| B | توکن تمایزدهنده: عدد، توکن لاتین، نام خاص، «جلد ۲»، نامِ پس از «از/نوشته/اثر» |
| C | قانون ادغام |

```
اگر similarity(normalized_title) < 0.80  →  ادغام نکن

اگر similarity >= 0.80:
    توکن‌ها یکسان                    →  ادغام کن (confidence = high)
    یکی از دو طرف توکن خالی دارد    →  needs_review = True، ادغام نکن
    توکن‌ها متفاوت و هر دو پر       →  ادغام نکن (خط قرمز)
```

**قانون طلایی در کد اعمال شده، نه فقط در توضیحات:** خوشه‌بندی حریصانه است ولی
هر اتحاد قبل از اجرا چک می‌کند که هیچ جفت «خط قرمز» داخل خوشه نیفتد — یعنی حتی
مسیر انتقالی (آوا ~ بدون‌نام ~ مهسا) هم نمی‌تواند دو محصول متفاوت را یکی کند.

سناریوی مرجع در `tests/test_resolver.py` قفل شده است:

| عنوان | توکن تمایزدهنده | نتیجه |
|---|---|---|
| رمان تاوان خیانت آوا | `{آوا}` | با نسخه‌ی «دانلود ... pdf» ادغام می‌شود |
| رمان تاوان خیانت مهسا | `{مهسا}` | خط قرمز — جدا می‌ماند |
| رمان تاوان خیانت از ناشناس | `{}` | `needs_review` — ادغام نمی‌شود |
| رمان تاوان خیانت ۴ برادر | `{۴ برادر}` | خط قرمز — جدا می‌ماند |

تصمیم‌های هر اجرا در `data/review/<run_id>_merge_decisions.json` لاگ می‌شوند.

**یک ریسک باقی‌مانده:** طبق قانون داکیومنت، «توکن‌های یکسان → ادغام» شامل حالتی
هم می‌شود که *هیچ‌کدام* از دو عنوان توکن تمایزدهنده ندارند. یعنی «رمان شب سرد» و
«رمان شب گرم» (شباهت ۰.۸۶) ادغام می‌شوند. اگر این برایتان خطرناک است،
`resolve.empty_token_threshold: 0.95` را در config بگذارید تا این جفت‌ها به‌جای
ادغام، به شیت C بروند. پیش‌فرض، رفتار دقیق داکیومنت است.

### فاز ۳ — گوگل ساجست

Endpoint غیررسمی `suggestqueries.google.com`. قواعد ایمنی **در خود کلاینت**
اعمال شده‌اند تا قابل دور زدن نباشند:

- تأخیر تصادفی ۲ تا ۴ ثانیه بین درخواست‌ها (پاسخ‌های کش‌شده تأخیر ندارند)
- حداکثر ۳۰۰ کوئری در هر نشست
- هر نتیجه در `api_cache` — اجرای دوباره کوئری تکراری نمی‌زند
- سه پاسخ خالی یا خطای پشت‌سرهم → توقف با پیام، بدون از دست رفتن داده‌ی قبلی

پس از توقف، `--resume-from 3` فقط محصولات باقی‌مانده را می‌گیرد. اگر واقعاً
محصولاتتان ساجست ندارند، `suggest.max_consecutive_failures` را بالا ببرید.

نتایج در `lsi_keywords` (یک ردیف به‌ازای هر کلمه). اگر یک کلمه به دو محصول نسبت
داده شود، فقط برای محصولی می‌ماند که شباهت متنی بیشتری دارد. نتیجه‌ی خالی →
`no_suggest` و رفتن به شیت B (رکورد حذف نمی‌شود).
